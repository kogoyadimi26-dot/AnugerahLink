# Security audit: AnugerahLink

Date: 18 November 2026. Scope: all application code in `lib/`, `server.js`, `public/`, `config/`, `scripts/`. Method: code review, targeted searches for common risks, the full automated test suite (162 tests), and an end-to-end run on a fresh server that exercised the buyer and staff flows and the security controls.

## Result

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | Medium | Payment and courier webhooks accepted any signed message, so a captured request could be replayed later. | **Fixed.** The signature now covers a timestamp, and messages older than 5 minutes (or dated in the future) are refused. |
| 2 | Medium | Guest order lookup (`number` + `email`) and guest feedback had no rate limit, so the email could be guessed in bulk. | **Fixed.** 30 failed lookups per IP per 15 minutes, then a lockout. |
| 3 | Low | Buyer signup had no rate limit. | **Fixed.** 30 signups per IP per hour. |
| 4 | Low | Buyer passwords needed only 8 characters. | **Fixed.** Minimum is now 10. |
| 5 | Low | No `Strict-Transport-Security` header. | **Fixed.** Sent on every response; browsers only honour it over HTTPS. |
| 6 | Low | The backup destination was placed into a SQL string (`VACUUM INTO`). It is operator-set, but a quote in the path would break the statement. | **Fixed.** The path is checked before anything touches the disk. |
| 7 | Low | A disabled checkout link used an inline `onclick`, which the CSP blocks. | **Fixed.** Replaced with a page-wide guard. |
| 8 | Low | `.env` files were not git-ignored. | **Fixed.** Added to `.gitignore`. |

Verified as sound (no change needed):
- Every admin API route has a permission check (checked across multi-line definitions).
- Buyer data is owner-scoped: another buyer gets 404 on a proposal they don't own.
- Passwords are hashed with scrypt; session tokens are random and stored as SHA-256 hashes; buyer sessions expire.
- Login errors are identical for a wrong password and an unknown email; login is rate limited per email and per IP.
- Password reset answers the same whether or not the email exists, and is rate limited.
- Output escaping: user-entered text goes through `esc()`. Theme colours accept only `#RRGGBB`. Photo uploads accept only JPEG/PNG data URLs, capped at 2 MB.
- Static file serving resolves paths and refuses anything outside `public/`.
- Production refuses to start with demo accounts, the default owner password, or dev reload (`lib/prodcheck.js`).
- Request bodies are capped at 3 MB; security headers include CSP, `X-Frame-Options: DENY`, `nosniff`, and `Referrer-Policy`.
- No npm dependencies (small supply-chain surface).

## Open risks (not changed; need a decision or a bigger change)

| # | Severity | Risk | Recommendation |
|---|---|---|---|
| A | Medium | Session tokens are kept in `localStorage` / `sessionStorage`. A script injected in the page could read them. | Move to `HttpOnly; Secure; SameSite=Strict` cookies, and add a CSRF token for state-changing requests. Planned as a separate change. |
| B | Low | Signup returns "email already registered" (409), which reveals whether an email has an account. | Answer generically and confirm by email. This changes the sign-up flow, so it needs your decision. |
| C | Low | CSP allows `style-src 'unsafe-inline'`, which the page needs for inline `style=` attributes. | Move inline styles into classes, then drop `unsafe-inline`. |
| D | Low | Rate limits and replay-safety are in memory. They reset on restart and are not shared across several server instances. | Keep one instance, or move the counters to a shared store before scaling out. |
| E | Low | A webhook captured inside its 5-minute window could be sent again. The handlers are idempotent (repeats are recognised), so the effect is limited. | Add a nonce store if providers ever need stricter guarantees. |
| F | Info | `node:sqlite` is experimental in Node 22. | Pin the Node version and watch Node release notes. |
| G | Info | Demo accounts and the demo payment simulator exist. They are disabled only when `DEMO_ACCOUNTS` is unset. | Never set `DEMO_ACCOUNTS=1` on the live server (already blocked in production mode). |
| H | Info | Photo uploads are checked by their declared type, not by file contents. | Acceptable: files are served with their stored type and the `nosniff` header. A content check could be added. |

## Verification

- `npm test`: 162 passing (includes `test/security.test.js`, 7 new tests).
- End-to-end run on a fresh server: 32 of 33 checks passed. The one failure was a wrong expectation in the check itself (the server correctly returns 503 when no webhook secret is set); re-checked with a secret configured: unsigned, stale and tampered requests return 401, and a fresh valid signature passes verification.
- Browser: home, product, about, admin dashboard, admin proposals and buyer proposals render with no page errors and no horizontal overflow.
